VaultBook (formerly OfflineBooks US) — storage schema
=====================================================
App 1.18.0 · IndexedDB company schema version 5 · company data version 8.
Storage names keep the OfflineBooksUS prefix (never renamed).

DATABASES (IndexedDB, per browser profile)
  OfflineBooksUS                  registry
    companies   keyPath id        { id, name, createdAt, lastOpened }
    settings    keyPath key       { key: 'lastCompany', value }
  OfflineBooksUS_<companyId>      one per company (IndexedDB schema version 5)
    company         keyPath id    company record (one row)
    accounts        keyPath id
    contacts        keyPath id    customers and vendors (kind)
    transactions    keyPath id    indexes: date, type
    rules           keyPath id
    recurring       keyPath id
    reconciliations keyPath id
    audit           keyPath id    append-only
    meta            keyPath key   (added in v2) { key: 'security', ... } when protected
    classes         keyPath id    (v3) class tracking list
    budgets         keyPath id    (v3)
    reports         keyPath id    (v3) saved (memorized) reports
    items           keyPath id    (v4) products & services
    attachments     keyPath id    (v5) { id, ownerId, name, type, size, data (data URL), addedAt, deleted }

MONEY
  Integer cents everywhere. A split amount > 0 is a debit, < 0 is a credit.

TRANSACTION RECORD
  { id, type, date (YYYY-MM-DD), number, contactId, memo, accountId,
    lines: [{ accountId, description, qty, rate, amount, itemId, classId, taxable }]  item types
    jlines: [{ accountId, debit, credit, contactId, memo }]      journal
    amount, toAccountId                                          payment/transfer types
    applications: [{ txnId, amount }]                            payments & credits
    dueDate, terms                                               invoices/bills/estimates/POs
    taxId, taxableAmount, taxRate, tax                           sales tax (1.13): invoice, sales receipt,
                                                                 credit memo, estimate. taxRate = rate used,
                                                                 in millionths (8.25% = 82500)
    message                                                      customer message printed on sales documents
    sourceId                                                     invoice/bill made from an estimate/PO
    linkedTo: [txnId]                                            estimate/PO -> documents made from it
    splits: [{ accountId, amount, contactId, memo, cleared: ''|'C'|'R' }]
    total, status: 'posted'|'void' ('open'|'closed'|'void' for estimate and
    purchaseOrder, which never post: splits = []), version, createdAt, updatedAt,
    voidedAt, voidReason, reversalOf, reversedBy, clientToken, importHash, recurringId }
  splits are always rebuilt from the source fields and must sum to zero.
  Sales tax adds one split to the rate's liability account (company.salesTaxes[].accountId).

COMPANY RECORD (additions)
  statementLook (1.40): layout of the Balance Sheet and Profit and Loss, one of
    classic lines grid two banded formal boxed pad bars step dense big; missing = classic.
  salesTaxes: [{ id, name, agency, rate (millionths), accountId, active }], defaultSalesTaxId,
  closingDate, closingHistory: [{ at, from, to }], closingPasswordSalt, closingPasswordHash
  (iterated salted SHA-256, a gate on moving the closing date — not encryption),
  customerMessages: [text], logo (image data URL), counters { ..., estimate, purchaseOrder }.
  Contacts (customers) may carry taxExempt and salesTaxId.

INVENTORY AND FIXED ASSETS (1.15)
  item: trackQty, reorderPoint, assetAccountId (Inventory Asset), expenseAccountId (COGS).
  Sales-type lines of tracked items carry cost, cogsAccountId, assetAccountId (average cost at posting);
  buildSplits adds Dr COGS / Cr asset (reversed on credit memos). Purchase lines of tracked items
  post to the asset account and need a quantity.
  type 'invAdjust': { accountId, adjustments: [{ itemId, qty, value, memo }] } — value defaults to
  qty x average cost. Average cost = asset value / qty, walked in date order (Book.inventoryState).
  company.fixedAssets: [{ id, name, inService, cost, salvage, method 'SL'|'DDB'|'MACRS', lifeMonths,
  macrsClass, accountId, accumAccountId, expenseAccountId, disposed }]; depreciation journal entries
  carry depreciation: true and jlines[].assetId.
  Deposits (1.14): deposit lines may carry fromTxnId (a payment moved out of Undeposited Funds).
  check / billPayment / expense may carry toBePrinted, printedAt; invoice financeCharge;
  credit memo writeOffOf; contact w9OnFile; company checkAlign, checkCompanyBlock, financeCharge.

JOBS, BILLABLE COSTS, TAX LINES (1.16)
  contact (customer): parentId (Customer:Job), jobStatus, jobStart, jobEnd, jobType.
  bill / check / expense lines: contactId (customer or job) and billable; invoice lines: billOf
  = '<txnId>:<lineIndex>' of the cost being re-billed (each cost billed once, by a posted invoice).
  company.taxForm '1040C'|'1120S'|'1065'|'1120' and taxLines { accountId: line code }.

SALES WORKFLOWS (1.17)
  type 'salesOrder' (non-posting, converts to invoice). Converted document lines carry srcLine (index
  of the source line); the source closes when every line is fully invoiced / billed (sourceProgress).
  company.priceLevels [{ id, name, method 'pct'|'item', pct, prices { itemId: cents } }]; contact
  priceLevelId. Customer deposits: a sales receipt line to the Customer Deposits liability; applied
  with a negative invoice line to that account (an invoice may total 0 when a deposit covers it).

SALES TAX BY AGENCY (1.18)
  salesTaxes[].components [{ name, agency, rate }] (rate = their sum); documents keep taxParts
  [{ agency, name, rate, amount }] (tax split with exact cents). Sales tax payments are check /
  expense lines to the liability carrying taxAgency. Contact exemptCert { number, state, reason, expires }.

AUDIT TRAIL (1.13)
  audit entry = { id, ts, action, txnId, summary, before, prev, hash }
  hash = SHA-256( prev + '|' + stableJSON({ id, ts, action, txnId, summary, before }) )
  prev = hash of the entry before it ('' for the first chained entry). Book.verifyAudit()
  and Data integrity report changed entries, missing entries and extra starting points.
  Entries written before 1.13 have no hash and are listed as not chained.

PASSWORD PROTECTION (encryption at rest)
  When a company is protected, every record in every store except 'meta' is
  stored as  { id, enc: { v: 1, iv: Uint8Array(12), ct: ArrayBuffer } }
  ct = AES-GCM-256( JSON(record) ), additional data = "<store>/<id>".
  meta.security = { version, cipher, password: W, recovery: W, hint,
                    autoLockMinutes, enabledAt, changedAt }
  W (wrapped data key) = { kdf: 'PBKDF2-SHA256', iterations, salt, iv, wrapped }
  password: 600,000 iterations; recovery key (160-bit random): 100,000.
  Encrypted backup file = { format, encrypted: true, appVersion, createdAt,
    companyName, security: {password: W, recovery: W, ...},
    payload: { iv, ct } }  where ct decrypts (AAD "backup") to a normal backup.

TWO KINDS OF MIGRATION
  1. IndexedDB structure: COMPANY_UPGRADES in js/db.js, applied in onupgradeneeded
     for each version step. v1 -> v2 adds the 'meta' store; v3 classes, budgets,
     reports; v4 items; v5 attachments.
  2. Company data format: schema.DATA_VERSION and schema.MIGRATIONS in
     js/schema.js. Applied when a company is opened (results saved in one atomic
     write) and when a backup is restored. Data from a NEWER app version is
     refused rather than misread. Current data version: 8
     (v2 counters/rules, v3 classes/budgets/reports, v4 items, v5 sales tax rates,
     estimate/PO counters, closing history, STAX system account; v6 invAdjust counter,
     INV system account, fixed asset register; v7 attachments list, taxForm, taxLines; v8 salesOrder counter, priceLevels).

BACKUP FILE (JSON)
  { format: 'OfflineBooksUS-Backup', appVersion, dataVersion, createdAt,
    companyName, counts, checksum: 'crc32:..-fnv:..-len:..', data: {company, accounts,
    contacts, transactions, rules, recurring, reconciliations, audit, classes, budgets,
    reports, items} }
  Checksum is computed over a key-sorted serialization of data.

Saved reports with report: 'designer' (1.10) keep the template in params.def:
{ format: 'vaultbook-report-template', version: 1, name, kind: 'pl'|'bs',
  period: { range, from, to }, basis: ''|'cash'|'accrual', columns: { by, compare[] },
  rows: [{ id?, type: 'accounts'|'formula'|'header'|'text'|'spacer', label, totalLabel,
           select: { types[], numbers, match, accounts[], rest, netIncome }, detail, sign,
           formula, format: 'money'|'pct'|'ratio', style: { bold, italic, indent, line,
           pageBreak, hideZero }, cond: { op, value, style } }] }
Full JSON Schema: OB.designer.SCHEMA (js/designer.js). No new IndexedDB store or version.

-------------------------------------------------------------------------------
New store bankLines: { id, accountId, importId, seq, date, description, amount (cents,
  + = money in), checkNo, balance (cents|null), hash (import fingerprint), status:
  'review'|'posted'|'excluded'|'removed', createdAt, [posted] txnId, splitIndex, via:
  'add'|'transfer'|'split'|'open'|'match', postedAt, categoryId, contactId, clearedBefore,
  [excluded] excludeReason, excludedAt }.

  dateFrom, dateTo, endingBalance (cents|null), endingDate, undone?, undoneAt? }.

1.23.0 (Bank rules v2, several entries per bank line, already in the books, reconcile) — no schema change; optional fields only

  when finished with a difference (journal entry to the "Reconciliation Discrepancies" expense account,
  voided when the reconciliation is undone).
